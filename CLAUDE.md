## Comments

Never write comments that explain how the code works — the code speaks for itself. Do not narrate mechanics, restate logic, or add "what this does" prose. If something needs explaining, explain it in the conversation, not in the source. Comments are reserved only for non-obvious *why* (rationale, gotchas, external constraints) that cannot be inferred from reading the code.
